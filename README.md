# Berkay Özgün Portfolio

A bilingual portfolio built with Next.js App Router, React, TypeScript and Tailwind CSS. It presents selected projects, skills, work experience, education and contact links.

## Requirements

- Node.js **24.x** (see `package.json`)
- npm
- Internet access during installation and production builds: `next/font/google` downloads Inter and JetBrains Mono at build time. Fonts are subsequently served by the application, not requested from Google by visitors.

## Local development

From the repository directory:

```sh
npm ci
npm run dev
```

Open <http://localhost:3000>. If that port is occupied, use the URL printed by Next.js.

## Commands

| Command | Purpose |
| --- | --- |
| `npm run dev` | Start the development server |
| `npm run build` | Create a production build in `.next/` |
| `npm start` | Serve an existing production build |
| `npm run lint` | Run ESLint |
| `npm run typecheck` | Check TypeScript without emitting files |
| `npm test` | Run the Vitest regression suite once |

## Features

- Turkish and English content, with a shared language control on desktop and mobile.
- Language preference stored in browser `localStorage` when available; the document language follows the selection. English is the server-rendered default.
- Light and dark themes, with dark as the initial default.
- Responsive project grid and Radix project detail dialogs, including keyboard controls and focus restoration.
- Project previews and privacy explanations; status is displayed only when provided in the project data.
- Reduced-motion support for scrolling, hero animations and CSS effects.
- Email copying, email links, GitHub and LinkedIn links.
- Page metadata, `robots.txt` and `sitemap.xml` generated by Next.js.

## Project structure

```text
src/
├── app/                  # App Router page, root layout, robots and sitemap
├── components/
│   ├── Portfolio.tsx     # Locale, navigation and selected-project state
│   ├── ProjectModal.tsx  # Project detail dialog
│   ├── sections/         # Hero, projects, experience, education, contact
│   └── ui/               # Reusable UI primitives
├── data/                 # Bilingual profile and project content
├── i18n/locales/          # Shared English/Turkish interface copy
├── lib/                  # Utilities
├── test/                 # Vitest DOM setup
├── types/                # Content types
└── index.css             # Global styles and reusable classes
```

Component tests live beside the components as `*.test.tsx`. They cover locale persistence, server/client hydration, document language, theme switching, reduced-motion scrolling, native project buttons, image fallback resets, modal descriptions/focus restoration, gallery navigation and privacy tooltip interactions. These DOM tests do not replace real-device, visual or screen-reader testing.

## Updating content

- Edit both `en` and `tr` entries in `src/data/profile.json`. Keep project IDs consistent across languages so an open project's content can follow language changes.
- Shared interface text lives in `src/i18n/locales/en.json` and `tr.json`. Project preview, modal and terminal labels also have typed bilingual maps in their components.
- Project status is optional (`links.status`). Omit it when the state is unknown; previews do not infer a shipped status.
- Update metadata in `src/app/layout.tsx`, and keep the origin in `src/app/robots.ts` and `src/app/sitemap.ts` aligned with the deployed domain.
- Contact details are in the hero and contact section components.

## Dependency security

Install from the committed lockfile with `npm ci`. Check both the complete dependency tree and production-only dependencies:

```sh
npm audit
npm audit --omit=dev
```

The security update uses Next.js 16.4.3 or later within the 16.x range, removes the unused HTTP translation backend and keeps ESLint tooling in `devDependencies`. `@eslint/js`, imported by the lint configuration, is declared explicitly rather than relying on a transitive dependency.

The application uses React 19 with matching React DOM and TypeScript types, and ESLint 10 with compatible TypeScript/React plugins. Fast Refresh uses the Next.js preset so framework-supported metadata exports are valid; reusable CVA variants live separately from component modules. A clean audit only means no known advisories were reported at the time of the check.

## Production deployment

Use a host supporting Next.js, such as Vercel, or a Node.js 24 environment:

```sh
npm ci
npm run build
npm start
```

The default production server listens on port 3000. This project is **not** configured as a static export: do not deploy `.next/` as plain static files or look for a Vite `dist/` directory.

### Restricted build environments

If Turbopack fails with `binding to a port: Operation not permitted` in a sandbox, run `npm run build -- --webpack` to validate the production build using Webpack. The default build command remains Turbopack.

### Font download failures

Production builds need access to `fonts.googleapis.com` and `fonts.gstatic.com`. If that access is blocked, configure your build environment's network/proxy access or replace the Google font loaders in `src/app/layout.tsx` with licensed, locally stored font files via `next/font/local`.
